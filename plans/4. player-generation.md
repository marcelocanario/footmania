# Player Generation System — Technical Specification

**Document Type:** Engine Technical Specification  
**Status:** Implementation Ready  
**Scope:** Player generation for new senior squads and youth academies in the multiplayer division pyramid  
**Canonical Companion Spec:** `player-development.md`  
**Out of Scope:** Changes to the existing development/decay formulas, transfer-market rules, scouting, coaching, facilities, morale, injuries, retirement

---

# 1. Purpose

This specification replaces the existing club-level-driven player generator with a division-driven statistical model.

The design goal is:

```text
Some players are born bad.
Most are born ordinary.
Some are born good.
A few are born exceptional.

Then, independently:

Some develop slowly.
Most develop normally.
Some develop quickly.
Some decline early.
Some decline late.
Playing time affects development as already specified.
```

The combination of starting quality plus the existing development system must create the player's career.

The generator MUST NOT try to predetermine the player's final career quality.

The intended multiplayer ecosystem is:

```text
lower division
    ↓
occasional strong prospect / strong player
    ↓
development
    ↓
player becomes attractive to stronger clubs
    ↓
trade / auction
    ↓
talent gradually moves upward through the pyramid
```

Higher divisions MUST be stronger on average, but no division may have an exclusive quality range.

---

# 2. Non-Negotiable Design Rules

The implementation MUST satisfy all of the following:

1. `club.level` is removed completely.
2. New senior squad quality depends only on the club's current division.
3. Youth quality depends only on:
   - current division;
   - highest-ever division reached.
4. Higher divisions shift the expected player-quality distribution; they do not change its theoretical ceiling.
5. Lower divisions must be capable of producing rare excellent players.
6. Starting quality is independent from:
   - `developmentRate`;
   - `developmentVolatility`;
   - `declineStartAge`.
7. Existing player growth/decay formulas remain unchanged.
8. Human and AI clubs use exactly the same generation formulas.
9. No explicit star/starter/bench/depth quality roles are generated.
10. No separate random "wonderkid" event exists.
11. Academy releases cannot be used to reroll youth.
12. All generation uses deterministic server-side RNG.
13. The specification contains canonical Version 1 values. The implementer must not invent balance values.

# 5. Rating-Scale Normalization

Generation formulas MUST work against the engine's configured OVR range.

Let:

```text
OVR_MIN = engine's authoritative minimum possible OVR
OVR_MAX = engine's authoritative maximum possible OVR
R       = OVR_MAX - OVR_MIN
```

All Version 1 generation constants are defined relative to `R`.

For a conventional approximately `1–100` rating scale, the resulting values are shown throughout this document for intuition.

Do NOT change the engine's existing skill/OVR bounds.

# 6. Minimal Quality Tuning Surface

The quality model exposes four meaningful designer-facing knobs:

```text
TOP_DIVISION_MEAN_OVERALL     = 73.50
PLAYER_QUALITY_SPREAD_OVERALL = 6.00
DIVISION_OVERALL_SPAN         = 18.00
ACADEMY_PEDIGREE_OVERALL_BOOST = 25.50
```

Everything else is mathematically derived or is a fixed Version 1 constant.

Interpretation:

### `TOP_DIVISION_MEAN_OVERALL`

This is the absolute quality anchor for generated Division 1 senior players.
It is intentionally independent from the player spread so designers can move
the whole pyramid without changing within-division variance. With the current
30-player roster and lineup selection, `73.5` produces an automatic starting XI
of approximately `78 OVR`; setting this to `78` would instead make the whole D1
generated player pool approximately `78` and the selected XI materially higher.

### `PLAYER_QUALITY_SPREAD_OVERALL`

\[
\sigma = 6.00\ OVR
\]

On a 1–100 scale:

```text
σ = 6.00 OVR
```

Approximately 6 OVR.

This controls how much individual players differ within the same environment.

### `DIVISION_OVERALL_SPAN`

The mean difference from the lowest division to Division 1 is:

\[
\Delta_{division}=18.00\ OVR
\]

On a 1–100 scale:

```text
18.00 OVR
```

Approximately 18 OVR.

### `ACADEMY_PEDIGREE_OVERALL_BOOST`

The strongest possible academy pedigree shifts the youth mean by:

\[
25.50\ OVR
\]

On a 1–100 scale:

```text
25.50 OVR
```

This is an intentionally strong academy calibration: with regular starter
minutes, a current-and-historical Division 1 academy player peaks at
approximately `78 OVR` on average. Individual birth-quality variation still
produces substantial better and worse outliers.

# 8. Top-Division Absolute Quality Anchor

Configure the Division 1 generated-player mean independently from the quality
spread:

\[
\mu_{top}=TOP\_DIVISION\_MEAN\_OVERALL
\]

Reason:

The designer must be able to target a recognizable football-quality level for
Division 1 without also changing how varied players are inside a club. Spread,
cross-division separation, and the absolute level are separate decisions.

The player-quality distribution is truncated at `+3σ`.

Therefore the strongest normal generated D1 outlier is approximately:

\[
\mu_{top}+3\sigma
\]

The configured anchor SHOULD leave enough headroom that this value remains
below `OVR_MAX`, avoiding population pile-up and preserving room for development.

On a 1–100 scale:

```text
σ       = 6.00
μ_top   = 73.50
+3σ     = 91.50
```

So even an extreme D1 generation outlier is normally created below the hard cap.

---

# 9. Lowest-Division Mean Is Also Derived

The full division span is configured directly:

\[
\Delta_{division}=DIVISION\_OVERALL\_SPAN
\]

Therefore:

\[
\mu_{bottom}
=
\mu_{top}
-
\Delta_{division}
\]

On a 1–100 scale:

```text
μ_bottom = 55.50
```

This has a useful intentional property:

\[
\mu_{bottom}+\Delta_{division}
=
\mu_{top}
\]

With the current values, `DIVISION_OVERALL_SPAN = 3σ`, so an extreme `+3σ`
player generated in the lowest division starts approximately at the *average
Division 1 quality*. Spread and division span remain independently tunable.

This is rare, but possible.

That directly supports upward player mobility.

# 10. Canonical Division Strength Function

Let:

```text
D = current division number
N = total number of divisions
```

with:

```text
D = 1 → strongest
D = N → weakest
```

Use:

\[
S(D)=
1-
\frac{
\ln(1+0.5(D-1))
}{
\ln(1+0.5(N-1))
}
\]

For:

```text
N <= 1
```

use:

```text
S = 1
```

Clamp numerical floating-point error into:

```text
0 <= S <= 1
```

This logarithmic curve intentionally creates larger differences near the top and progressively smaller differences lower in the pyramid.

---

# 11. Division Mean Formula

For any division:

\[
\boxed{
\mu(D)
=
\mu_{bottom}
+
(\mu_{top}-\mu_{bottom})S(D)
}
\]

Equivalently:

\[
\mu(D)
=
\mu_{bottom}
+
\Delta_{division}S(D)
\]

There are NO hand-authored means for individual divisions.

# 13. Core Player Quality Draw

Every player's generation quality uses:

\[
Z \sim TN(0,1,-3,3)
\]

where `TN` means true truncated normal sampling.

Do NOT:

```text
sample normal
then clamp to ±3
```

because clamping creates artificial probability piles at the bounds.

Interpretation:

```text
Z ≈ -3.0   extreme poor outlier
Z ≈ -2.0   very poor
Z ≈ -1.0   below average
Z ≈  0.0   ordinary
Z ≈ +1.0   good
Z ≈ +2.0   excellent
Z ≈ +2.5   rare elite outlier
Z ≈ +3.0   extreme outlier
```

The normal distribution itself generates the "bad / okay / good / great" population.

No explicit player-quality categories are required.

---

# 14. Senior Current-Ability Formula

For every newly generated senior:

\[
\boxed{
OVR^*_{senior}
=
\mu(D)
+
\sigma Z
}
\]

where:

```text
Z ~ TN(0,1,-3,3)
```

`OVR*` is the target generated ability.

The final OVR remains derived from skills.

The generator MUST NOT create quality roles such as:

```text
star
starter
rotation
bench
depth
```

Those emerge automatically from order statistics across the generated squad.

# 15. Why a Separate Club-Strength Variable Is Unnecessary

If a squad contains `n` independently generated players with standard deviation `σ`, the squad mean itself naturally varies with:

\[
SE(\bar X)=\frac{\sigma}{\sqrt n}
\]

For the canonical 28-player squad and approximately `σ = 6`:

\[
SE \approx \frac{6}{\sqrt{28}}
\approx 1.13
\]

Therefore clubs in the same division naturally differ by roughly one OVR around the divisional expectation without introducing a separate club-quality roll.

Some generated clubs will be strong.

Some will be weak.

Most will be close to the division mean.

No `clubStrengthShock` is required.

# 20. Highest-Ever Division

Add:

```ts
club.highestDivisionReached
```

Division ordering:

```text
1 = best
larger number = worse
```

Update:

```ts
highestDivisionReached =
    Math.min(
        highestDivisionReached,
        currentDivision,
    );
```

For a newly created club:

```text
highestDivisionReached = initialDivision
```

For existing clubs:

1. derive the historically best division from reliable league history if available;
2. otherwise set it to current division.

Never invent a better historical division.

---

# 21. When Highest-Ever Division Updates

Do NOT update historical best merely because promotion has been secured.

Use this order:

```text
season ends
↓
promotion/relegation determined
↓
next-season divisions assigned
↓
new season becomes active
↓
highestDivisionReached updated
↓
new academy intake generated
```

Thus the club must actually enter the higher division before receiving permanent historical credit for it.

# 25. Canonical Youth Reference Quality

Use age 21 as the youth reference point because age 21 is the existing automatic senior-promotion boundary.

Define the *unadjusted* average age-21 academy graduate as:

\[
\boxed{
\mu_{21}
=
\mu_{bottom}
}
\]

Therefore an average age-21 youth from the weakest academy is approximately equal to an average newly generated senior in the lowest division.

This is deliberate:

- ordinary academy graduates are usable in lower divisions;
- good academy graduates can already be useful higher up;
- extreme lower-division prospects can be Division-1-quality;
- development after generation can move players further upward.

For a 1–100 scale:

```text
μ21 = 55.50
```

# 27. Closed-Form Expected Youth Growth

Let:

```text
Gstart = 18
Dref   = 30
Gmax   = 3.0
e      = 1.35
Aref   = 0.895
```

For:

```text
18 <= a <= 21
```

expected natural growth from age `a` to age 21 is:

\[
G(a,21)
=
A_{ref}
\frac{
G_{max}(D_{ref}-G_{start})
}{
e+1
}
\left[
\left(
\frac{D_{ref}-a}
{D_{ref}-G_{start}}
\right)^{e+1}
-
\left(
\frac{D_{ref}-21}
{D_{ref}-G_{start}}
\right)^{e+1}
\right]
\]

For:

```text
a < 18
```

use:

\[
G(a,21)
=
A_{ref}
\left[
G_{max}(18-a)
+
G(18,21)/A_{ref}
\right]
\]

The implementation MAY evaluate the same formula numerically through production growth functions, but the numerical result MUST match this closed form within floating-point tolerance.

# 29. Youth Current-Ability Formula

For a generated youth of age `a`:

\[
\boxed{
OVR^*_{youth}
=
\mu_{youth}(a)
+
\sigma Z + B_A
}
\]

where:

\[
B_A=25.50P_A
\]

and:

\[

\]

This is the complete youth current-quality formula.

No arbitrary `-23 youth OVR` penalty remains.

No hand-written age table is a tuning input.

The age table above is simply the evaluated result of the development mathematics.

# 33. Initial Potential Is Derived, Not Independently Tuned

The existing engine uses `player.potential` as a development ceiling.

Do NOT create another arbitrary potential distribution.

Instead calculate initial potential from the player's own existing development profile.

Potential should be high enough to allow the player's plausible natural growth, while the actual development engine decides whether that growth is realized.

# 34. Remaining Natural Growth Integral

Let:

```text
a = player's current precise age
D = player's declineStartAge
r = player's developmentRate

Gstart = existing growth reference age
Gmax   = existing max seasonal growth
e      = existing growth exponent
```

If:

```text
a >= D
```

then:

\[
RemainingGrowth(a,D)=0
\]

If:

```text
18 <= a < D
```

then:

\[
RemainingGrowth(a,D)
=
\frac{
G_{max}(D-G_{start})
}{
e+1
}
\left(
\frac{D-a}
{D-G_{start}}
\right)^{e+1}
\]

If:

```text
a < 18
```

then:

\[
RemainingGrowth(a,D)
=
G_{max}(18-a)
+
\frac{
G_{max}(D-G_{start})
}{
e+1
}
\]

`declineStartAge` is always at least 24 under the existing system, so `D > 18` is guaranteed for normal generated profiles.

# 35. Canonical Initial Potential Formula

Use the player's actual development rate and the existing random-factor maximum.

Do NOT apply an activity penalty because potential represents a ceiling, not an expected outcome.

\[
\boxed{
Potential_0
=
clamp
\left(
\left\lceil
OVR
+
RemainingGrowth(a,D)
\times r
\times R_{max}
\right\rceil,
OVR,
OVR_{MAX}
\right)
}
\]

where:

```text
r     = player.developmentRate
Rmax  = DEVELOPMENT.randomFactor.max = 1.20
```

Interpretation:

- starting quality determines where the player begins;
- `developmentRate` and `declineStartAge` determine how much natural development room should plausibly be available;
- the `1.20` factor is not a new tuning value—it is the existing maximum development random factor;
- actual realized growth still depends on the normal development engine and activity.

The existing weekly `potentialGrowth()` logic remains unchanged and may increase the ceiling for under-21 players afterward.

---

# 36. Why Potential Uses the Development Profile

This formula deliberately prevents potential from becoming a second unrelated destiny roll.

Examples:

```text
high developmentRate + late declineStartAge
→ larger natural ceiling

low developmentRate + early declineStartAge
→ smaller natural ceiling
```

But starting quality remains independent from those traits.

Therefore:

```text
poor starting player + strong development profile
```

can still have substantial room to improve.

And:

```text
great starting player + weak development profile
```

may have less remaining growth.

This is the intended interaction.

---

# 37. Tier Is Derived From the Birth-Quality Percentile

Remove club/division-based tier selection.

Use the original unshifted quality score:

```text
Z
```

not the pedigree OVR offset `B_A`.

This is important because `player.tier` currently affects weekly `potentialGrowth()`.

Using raw `Z` ensures academy pedigree does not indirectly modify future development through tier.

Use exact standard-normal percentile thresholds:

```text
10th percentile: -1.2815515655
30th percentile: -0.5244005127
70th percentile: +0.5244005127
90th percentile: +1.2815515655
```

Version 1 mapping:

```text
Z < -1.2815515655
    → Tier 1

-1.2815515655 <= Z < -0.5244005127
    → Tier 2

-0.5244005127 <= Z < +0.5244005127
    → Tier 3

+0.5244005127 <= Z < +1.2815515655
    → Tier 4

Z >= +1.2815515655
    → Tier 5
```

This yields approximately:

```text
Tier 1: 10%
Tier 2: 20%
Tier 3: 40%
Tier 4: 20%
Tier 5: 10%
```

before minor effects from truncation.

This assumes the current game's tier ordering is `1 = lowest` and `5 = highest`, consistent with the existing youth logic decrementing tier with `tier - 1`.

# 38. Development Traits Must Stay Independent

The RNG sequence MUST use separate draws for:

```text
starting-quality Z
```

# 39. Skill Generation

`OVR*` is a target only.

The player remains skill-based.

Pipeline:

```text
target OVR
↓
position
↓
private skill-shape recipe
↓
numeric skills
↓
actual OVR
```

Skill-shape recipes exist only while a player is being generated. Players have
no visible or hidden football-characteristic identifiers; recipe indexes are
never persisted and are never sent through APIs. Existing players are never
regenerated during this removal. Numeric skills remain authoritative for OVR,
lineup selection, development, and match simulation.

Recipe probabilities, recipe order, duplicate entries, step order, and the RNG
draw order are balance invariants. The recipe table must reproduce the existing
numeric-skill output exactly for every fixed seed.

Use:

```text
SKILL_TARGET_TOLERANCE_OVR = 1.0
SKILL_GENERATION_MAX_RETRIES = 8
```

Algorithm:

1. generate skills using the existing skill algorithm;
2. calculate actual OVR;
3. if `abs(actualOVR - targetOVR) <= 1`, accept;
4. otherwise retry deterministically, preserving the same position and target;
5. keep the closest attempt;
6. after eight attempts, accept the closest valid attempt.

No unbounded retry loop is permitted.

# 42. Academy Lifecycle — Fixed Mean Intake

Remove:

```text

```

This creates an academy reroll exploit.

Use a deterministic per-club/per-season quota derived from either an automatic
population-equilibrium calculation or a manually configured mean. Fractional
means use deterministic stochastic rounding, so the same club and season can
never reroll a different quota.

Canonical Version 1 structural values:

```text
INITIAL_ACADEMY_SIZE      = 11
ACADEMY_ROSTER_LIMIT      = 15
SEASONAL_ACADEMY_INTAKE   = "auto" (currently resolves to ≈ 2.26)
ACADEMY_PROMOTION_AGE     = 21
ACADEMY_CONTRACT_SEASONS  = 4
```

Rationale:

- `"auto"` replenishes the configured initial persistent-player population on
  average using the live retirement hazards, academy age mix, promotion age,
  and academy position weights;
- the quota is `2` in most club-seasons and `3` for approximately one quarter,
  with the draw keyed to stable world/club/season identity;
- `15` provides pipeline headroom without turning release into a reroll;
- `21` preserves the existing promotion rule;
- `4` preserves the existing youth contract rule.

Population-equilibrium calibration for persistent human clubs:

```text
mean field-player retirement age = 35.31
mean goalkeeper retirement age   = 38.28
position-weighted senior lifetime after age-21 promotion = 14.61 seasons
mean academy time for uniform ages 16–19                 = 3.50 seasons
target persistent players per club                       = 30 + 11 = 41
equilibrium intake                                        = 41 / (14.61 + 3.50)
                                                          ≈ 2.26 per season
automatic resolved mean                                   ≈ 2.26 per season
```

Ephemeral filler AI is excluded from this calculation because its entire
roster is destroyed and regenerated as a net-zero seasonal replacement.

# 43. Seasonal Intake Formula

At the normal intake point:

```text
availableSlots =
    ACADEMY_ROSTER_LIMIT
    - currentAcademyCount
```

Then:

```text
targetPopulation = INITIAL_SENIOR_SQUAD_SIZE + INITIAL_ACADEMY_SIZE
meanAcademyPipeline = ACADEMY_PROMOTION_AGE - mean(ACADEMY_MIN_AGE..ACADEMY_MAX_AGE)
meanSeniorCareer = expected survival seasons from the live retirement hazards,
                   weighted by academy position probabilities

resolvedMean = if SEASONAL_ACADEMY_INTAKE == "auto"
                 targetPopulation / (meanAcademyPipeline + meanSeniorCareer)
               else
                 SEASONAL_ACADEMY_INTAKE

wholeQuota = floor(resolvedMean)
fraction   = resolvedMean - wholeQuota
seasonQuota = wholeQuota + deterministicBernoulli(fraction, world/club/season)

intakeCount =
    min(
        seasonQuota,
        max(0, availableSlots)
    )
```

Unused intake slots are lost.

They are NOT banked.

Releasing youth before or after intake never changes that club-season's quota.

}
\]

The `1.20` is the existing development random-factor maximum, not a new generation setting.

# 78. Final Design Principle

Generation determines:

```text
HOW GOOD IS THIS PLAYER WHEN HE ENTERS THE WORLD?
```

The existing development system determines:

```text
HOW DOES HIS CAREER EVOLVE?
```

The two are deliberately not collapsed into one hidden "future quality" number.

A player's final career emerges from:

```text
birth-quality draw
+
current/historical academy context
+
developmentRate
+
declineStartAge
+
developmentVolatility
+
playing time
+
bounded development randomness
```

Higher divisions receive better populations on average.

Lower divisions retain rare high-quality outliers.

Those successful players can then move upward through the multiplayer transfer market.
